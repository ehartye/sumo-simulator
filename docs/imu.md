# PrimeHub tilt support

`PrimeHub().imu.tilt()` and `tilt(calibrated=True)` return a `(pitch, roll)` tuple in degrees. The synchronous subset fixes the neutral robot frame to forward +Z, left +X and up +Y in chassis coordinates. Positive pitch lowers the nose; positive roll raises the +X side. Both starting headings have the same neutral tilt. Custom `PrimeHub` mounting arguments and raw `calibrated=False` tilt remain unsupported.

[Pybricks' reference frame](https://docs.pybricks.com/en/stable/signaltypes.html#reference-frames) has X forward, Y left and Z up. Mapping that right-handed frame to this Y-up world requires left +X (`forward × left = up`). Historical mesh names call the -X wheel “left”; tilt uses the coordinate frame above without changing motor ports, mounting signs or geometry.

[Stable PrimeHub documentation](https://docs.pybricks.com/en/stable/hubs/primehub.html#pybricks.hubs.PrimeHub.imu.tilt) specifies neutral-relative pitch then roll and calibrated gyro/accelerometer data by default. The [pinned v4.0.1 binding](https://github.com/pybricks/pybricks-micropython/blob/v4.0.1/pybricks/common/pb_type_imu.c) returns floating-point angles despite the documentation's integer annotation: `pitch = atan2(-F, sqrt(U² + L²))`, `roll = atan2(L, U)`. The [pinned IMU implementation](https://github.com/pybricks/pybricks-micropython/blob/v4.0.1/lib/pbio/src/imu.c) supplies a gravity direction estimated from orientation and maps it into the configured robot frame.

The simulator derives that direction from chassis orientation, adds independent Gaussian angle noise with assumed 0.1-degree standard deviation, clamps pitch to ±90 degrees and wraps roll to [-180, 180). Samples share the existing 100 Hz cache and 1 ms hardware-call scheduler. Noise is deterministic by seed, robot and sample tick in a separate RNG domain. **The tilt error model is uncalibrated:** no measured accuracy, real firmware fusion, acceleration contamination, calibration transient, shock error or drift is reproduced. This is an approximation of a real onboard hardware signal; it supplies no ground speed, contact state or opponent pose. Inversion appears near ±180 degrees of roll, with the usual angle wrap discontinuity; roll is undefined at vertical ±90-degree pitch.

Tilt explicitly extended the previously frozen runtime to `sync-subset-v2`; prior `sync-subset-v1` runs and replay metadata remain unchanged. Server, CLI and tournament metadata identify `imuTiltModel: orientation-tilt-v1` and its assumptions. Motor forces, geometry, friction, gravity, referee and existing distance/reflection/heading RNG draws are unchanged. Frozen golden tests compare those channels, state, contacts, events and ultrasonic diagnostics against the pre-extension source for three seeds.

`sync-subset-v3` corrects the sign of program-visible `imu.heading()` to [Pybricks' clockwise-positive, startup-relative and unwrapped convention](https://docs.pybricks.com/en/stable/hubs/primehub.html#pybricks.hubs.PrimeHub.imu.heading). The [pinned projection](https://github.com/pybricks/pybricks-micropython/blob/v4.0.1/lib/pbio/src/imu.c) uses `atan2(-forward_left, forward_front)`. A physical left turn must therefore produce negative heading. Versions v1/v2 mistakenly exposed the opposite sign. The correction negates the accumulated yaw only at the heading RPC boundary; cached readings, noise/drift, mechanics, referee and observer output remain byte-for-byte unchanged.

Replay/snapshot `bots[i].sensors.heading` retains the **legacy absolute CCW yaw** plus its assumed sensor noise/drift; it is an observer field and is not the startup-relative CW value returned by `imu.heading()`. Existing v1/v2 evidence is preserved with its original runtime metadata and source hashes. Sources that rely on signed v1/v2 heading require new revisions for v3. An explicit internal CCW yaw conversion (`yaw = -hub.imu.heading()`) preserves an established policy's values and consumes the same single 1 ms hardware call. Sources using only `abs(heading)` are sign invariant. Tests verify physical left/right turns, both initial headings, unwrapping beyond one revolution, exact converted value/scheduler/state/event parity and the unchanged golden World observations.
